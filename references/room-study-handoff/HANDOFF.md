# Room Study 3D 原型 Handoff

> 状态说明：这是**项目文件形式的 Handoff**，用于把当前实现完整交给下一位开发者复现和继续工作。它不是 `codex-handoff` Skill 成功创建的新 Codex Thread。当前聊天没有获得该 Skill 要求的 `list_projects` / `create_thread` 返回结果，因此不能声称已经建立新的用户任务或 Thread ID。

## 目标

把用户提供的二维住宅平面图转成一个浏览器中可运行的沉浸式 3D 空间体验。客户需要能够从全屋总览进入每个房间，自由移动和转动视角，看到基础家具、厨卫设备和材质，同时调整一天中的时间和一年中的日期，直观看到太阳方向、色温、亮度和阴影发生变化。

第一步是先运行 `room-study-standalone.html` 或项目根目录 `index.html`，确认当前基线，再依据真实尺寸、朝向和所在地替换所有估算值。不要在没有这些数据时把当前模型解释为施工或精确日照结果。

## 当前实现与技术路线

项目没有使用 Unreal Engine，也没有依赖 Three.js。浏览器端使用原生 WebGL 2 + GLSL ES 3.00：一个单位立方体作为共享几何，各墙体和家具通过模型矩阵缩放 / 平移成不同对象。渲染器分两遍：第一遍从太阳方向绘制 1536 × 1536 深度阴影图，第二遍绘制最终颜色；阴影使用 3 × 3 PCF 过滤。窗户使用透明混合。

空间不是由 AI 在运行时自动识别的。当前 `src/model.js` 是根据源图手工解释出的坐标化户型。外轮廓约按 11.2 m × 6.8 m、层高 2.8 m 建立，这些数字都属于体验估算。主卧、次卧 / 书房、玄关、客餐厅、厨房和卫浴都有预设进入视点。床、柜体、书桌、椅子、餐桌、沙发、电视、橱柜、水槽、灶台、冰箱、浴缸、坐便器、洗手台等由基础盒体构成。

相机有两种模式。全屋总览使用 Orbit 球坐标相机，可拖动旋转和滚轮缩放；自由行走保存人物位置、Yaw、Pitch 和约 1.62 m 的视高。人物在 XZ 平面中使用半径约 0.17 m 的圆进行碰撞，墙体和主要家具使用 AABB。一次移动拆成小步并分别尝试 X / Z 方向，因此可以降低穿墙并产生贴墙滑动。

太阳光不是预渲染图片。`src/app.js::sunCalc()` 根据一年中的日序、太阳时、纬度与图纸朝向计算太阳高度和方向，并进一步控制太阳光强、暖冷色、天空色和环境亮度。因此拖动“时间”和“日期”会真实改变实时阴影方向。不过它没有经度 / 时区修正、大气折射、真实天气、周边建筑遮挡或建筑法规级计算。

## 已包含功能

当前可运行版本包含：全屋俯览、房间快速定位、双击地面进入对应区域、WASD / 方向键自由移动、Shift 加速、鼠标 / 触摸环顾、移动端虚拟摇杆、墙体与主要家具碰撞、全屋剖切开关、家具点击查看名称 / 说明 / 估算尺寸、三套材质主题、0–24 小时太阳时、1–365 日季节日期、纬度和图纸朝向控制、自动播放一天、实时太阳阴影、截图、浏览器全屏、原始平面图和假设说明弹窗以及操作帮助。

完整清单见 `docs/FEATURES.md`。实现细节见 `docs/IMPLEMENTATION.md`。

## 权威文件

- `index.html`：多文件开发版入口。
- `room-study-standalone.html`：可直接交付的单文件版。
- `src/math.js`：向量和 4×4 矩阵。
- `src/model.js`：户型、家具、碰撞体、房间视点和材质主题。
- `src/renderer.js`：WebGL 2、GLSL、阴影图和透明绘制。
- `src/app.js`：太阳模型、相机、漫游、碰撞、选择和 UI 事件。
- `styles.css`：全部页面样式和移动端适配。
- `public/floorplan.png`：用户提供的原始平面图。
- `build_standalone.py`：把项目打成单 HTML。
- `docs/FEATURES.md`：功能清单与未实现项。
- `docs/IMPLEMENTATION.md`：复现说明。
- `tests/smoke.py`：基础浏览器回归。

`references/assistant-ui-design.md` 是项目上下文中保存的 UI 设计参考；它不改变本 3D 渲染器的技术路线，也不应被当成 3D 引擎规范。

## 已知约束和被明确放弃的替代路线

1. 没有真实尺寸，所以没有采用 BIM / CAD 精确重建。
2. 为了让交付可以直接下载并运行，没有把 Unreal Engine 作为当前运行时。UE 更适合最终高保真演示，但部署体积和维护复杂度显著更高。
3. 没有依赖在线 Three.js CDN。当前核心运行路径完全在本项目中，可进一步构建成单 HTML。
4. 家具现阶段使用参数化基础几何，不声称达到厂家模型或照片级资产精度。下一阶段如果目标是高保真家具，应转向 Blender / glTF 资产，而不是继续用更多盒体模拟细节。
5. 太阳模型用于视觉预览，不用于建筑日照法规、采光系数或能耗结论。

## 验证

重新打包时至少执行：

```bash
node --check src/math.js
node --check src/model.js
node --check src/renderer.js
node --check src/app.js
python3 build_standalone.py
python3 tests/smoke.py
```

当前包在生成时已经完成 JS 语法检查和 Chromium / WebGL 2 基础 Smoke Test；结果写入 `tests/validation-report.txt`。Smoke Test 重点确认：页面可以创建 WebGL 2、应用初始化成功、场景对象存在、六个预设房间存在、太阳时间变化确实改变光照方向、家具碰撞生效并成功生成截图。

这不等于在用户所有实际设备上完成 GPU / 性能验收。Safari、移动设备和独立显卡的视觉差异仍需单独测试。

## 下一阶段建议顺序

1. 获取真实外墙尺寸、主要房间尺寸、层高、门窗尺寸。
2. 获取真实城市 / 经纬度、房屋朝向或测量北向。
3. 校准 `src/model.js` 所有坐标与家具尺度。
4. 如果追求照片级家具，增加 Blender → glTF / GLB 导出规范、LOD、纹理压缩和资产清单。
5. 将家具从静态对象升级成可编辑实体：稳定 ID、位置 / 旋转 / 尺寸、材质引用、碰撞代理、撤销 / 重做。
6. 增加墙体属性和承重信息后，才允许“拆墙 / 改墙”操作；不能从当前图片推断承重属性。
7. 如果需要接入现有 Agent，再定义 `scene state` JSON、编辑命令协议和持久化后端，不要让语言模型直接修改渲染器内部对象。
8. 做桌面 Chrome / Edge、Safari、iOS Safari、Android Chrome 的实机回归和性能预算。

## 风险与易碎状态

- 当前所有几何坐标都来自单张无尺寸平面图的人工解释，换图不能直接复用坐标。
- 碰撞是 2D 简化，不考虑复杂旋转家具的真实轮廓。
- 家具拾取是近似地面交点 + 邻近对象，不是精确网格 Raycast。
- 玻璃是 Alpha Blend，不是折射材质。
- 阴影图固定 1536，低端移动 GPU 可能需要降级。
- 单文件版适合演示；持续开发应使用多文件版本，避免在生成文件里直接修改逻辑。
- `/mnt/data` 属于本次会话的下载交付位置，不应作为生产服务器路径或 Git 仓库位置。
