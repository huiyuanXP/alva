# 项目定位
简化设计师与用户初次接触时的沟通分歧及基础信息收集流程。计划通过可视化界面引导用户提供基础数据，并利用 3D 模型重建家庭场景及对应设计。用户提出设计需求后，由 AI Agent 理解分析并直接调整家具内容。最终向设计师交付整理好的需求清单及业主需求原文，以便快速理解、核验并避免误解。

# 项目亮点
## 3d可视化
生成对应的 3D 家庭模型，并根据用户提出的更多家具需求、设计需求等实时更新 3D 可视化。3D可视化应包括3D的全局预览，以及在房屋中进行漫游等操作。
## 用户需求分析和痛点挖掘

### 需求分析
在场景式对话中，初始的几个问题包括用户的购房整体需求、需要几个人住这间房子等。这些用户基础画像构建完成后，进行用户需求分析。分析具体应该包括用户所展现出来的显示特征，如年龄、具体的喜好，进行一些生活习惯以及生活偏好上面的一些推断。举个例子，从用户的基础信息我可以看到，用户是一个 27 岁左右的大厂工作的年轻人。然后他可能展现出来会有一些爱好，用户在对话中展现出他想要在房间里面布置更多的绿植，那么我可以推断他是一个比较喜欢自然这一类风格的用户。那么我可能会在房屋里面可以选择设置全落地窗或半落地窗的选项的时候，更多的就选择全落地窗，以此来保证房屋的光照。同时对房屋的整体风格可以进行一些改动，比如说使用更淡的颜色，或者使用更活泼的设计。和颜色、风格等。

### 痛点挖掘
痛点是那些因为用户的习惯、需求或者对应的特性导致可能会产生，但自己没意识到，或只有在实际使用/生活中才会发现的问题。我们要做的就是进行生活层面的模拟，提前发现并暴露这些问题。

#### 设计问题分析
我认为这个方面的一个例子就是，如果说我们的用户是一个爱喝咖啡的人，那么他们可能会倾向于做一个咖啡角。这个时候有很多设计师，他为了做美观一些，他就会让这个咖啡角它的宽度刚好等于这个咖啡机的宽度。那这个时候，用户他在做咖啡的时候，他就需要将已经装好粉的、那个用来接咖啡豆粉的东西，得拿着过去放到咖啡机里面，在移动的过程当中，可能就会造成咖啡粉它落在台面上或者落在地上，造成新的清洗麻烦。但是我们考虑到用户他的这一个做咖啡的需求的时候，那我就可以让这个台面它更宽一点，保留一个操作空间。你这种的话就是我们所说的设计问题分析。

####痛点挖掘
狗狗有时候会叼着球到处乱丢。如果家具设计有抬高部分，玩具可能会掉进去，很难拿出来，这很麻烦。所以家里有宠物的话，可以设计不抬高的沙发，避免玩具滚进去难拿出的情况。


## 冲突/可行性审查
我们要审查的有：
1. 几何重叠冲突
2. 动线冲突，比如动线互相碰撞，或拐角太小导致容易碰撞到家居或墙体等
比如我想在左边放一个绿植，把桌子、椅子往右边挪一点，但这会挤占整体活动空间，或者让另一个活动空间存在安全隐患。比如这里凸出来一块，可能会撞到，这也是一种风险。
3. 风格冲突，比如两个相邻区域风格的割裂, 或两个区域的行为互相造成影响，导致冲突
比如厕所和餐厅或厨房离得太近，或者一个区域需要安静的环境，另一个区域本质上有交流的需求和意义，导致两个区域之间的行为产生冲突
4. 用户提出的设计需求与其原本的用户画像定义或提出需求的目的存在冲突。
例如，用户画像定义其为喜欢大自然的人，因此我们会为其提供更多光照；但用户想要的设计（如在此处增加一张桌子或一个柜子）会对光照造成遮挡。此时需要提醒用户其本质需求与设计上的冲突，让用户自行决策。
5. 家具设计问题，
如家具承载力不足、空间容纳性不足等。比如，用户希望一个家具使用木质桌腿和石质桌面，木质桌腿可能会导致其负载不足，导致直接断裂；或者，用户希望书柜使用轻质材料，而轻质材料的承重力不足，导致书柜无法承受重物等。





## 家具自由编辑
家具自由编辑应当做成一个统一的功能接口或 MCP CLI 等方式，以供后续所有内容统一调用使用。
根据用户需求生成对应的家具 3D 模型，并允许用户自由移动位置。家具模型可复用，可同时出现多个相同的模型，赋予不同的 ID 即可。模型可以自由调整其长、宽、高等基础数据，材质或颜色等也应当可调。可调接口通过对应的数据接口实现，用户的 Chat 页面应当可以调用这些接口，对任意一个家具进行调整，或对多数家具进行批量调整。


## room Chat
本项目的定位是与顾客进行一种方便的沟通形式，所以其所有的功能应当是基于 Chat 收集用户的需求，然后由 Chat Agent 自行调用对应的功能完成相对应的需求更改、房间设计等。Chat 是用户交互的主要界面和入口，Chat 功能需要支持多模态输入，如图片、语音等。使用现成的包或相关 UI 服务提供基础 Chat 功能，后台接入 Codex 进行整体 Agent 操作。因此，需考虑将所有接口及相关改动功能以合适方式暴露给 Codex，例如做成 Prompt、Skill、MCP、CLI 等。

### 初始化引导
用户的基础界面就应当为 Chat 界面，因为此时用户没有提供任何相关的建筑图等，所以基础的初始化消息应当是引导用户提供相关的建筑信息，如建筑设计平面图或者相关的内容，使 Agent 首先能够建立一个基础的房屋 3D 模型。
```Chat
agent: 你好，我是你的房屋规划助手。你已经有一个理想中的房子了吗？可以给我这个房屋的户型图或者全局视图，我来为你建立房屋的整体概览和 3D 模型。
user: 提供相关的文字需求和图片或其他文件形式
background: 分析图片、文字等内容，并构建对应的3D视图
# 更新3D视图并进入正式化界面
```

### 房间定位
对于房间的规划定位，需要询问用户细节：
1. 如这个房间是卧室，你希望几个人住？需求和喜好是什么？
2. 如这个房间是储藏室，那么储藏室计划存储什么样的东西？需要做多少的功能分区等。
我举个更恰当的例子：比如我有很多运动器材，我可以告诉系统我要放几把球拍，比如网球拍，这样就能判断出我在运动方面相对专业。那对于这类在运动上比较专业的人，家里是不是需要一个地方来放奖杯或奖牌？我觉得这点很打动人。用户可能在任何时间提供更多的相关信息，需要随时考虑更新用户画像或者用户需求等全局字段

## 问卷
根据提供的问卷，在右侧栏提供问卷入口。用户可通过 Chat 随时更新问卷，也可通过右侧问卷入口手动填写相关问题，两者应当联动。当用户从问卷入口退出后，Chat 端应根据用户新提供的问卷信息进行一次分析，并为用户提供更多的房间建议。

## 更改预览
Chat 界面或用户要求的更改应当先生成更改预览。更改预览应当是一个可预览的 3D 场景，包括周围小范围的不变动物体和当前更改的物体。3D 场景支持拖动、旋转、放大等操作。

### 小变动
每次更改应当输出多个版本供用户选择，除非用户需求极为详细，此时只输出符合需求的版本。若用户需求简单（如“换个颜色”或“换更活泼的风格”），则应输出两个及以上版本，供用户选择后再确定最终版本。

### 大变动
对于更改范围大，或者同时需要更改多个家具、多个房间的场景，用户需求存在冲突或者模糊的情况, 无法识别用户需要更改哪些内容,需提供对应的更改选项卡：

1. 默认选择用户已提出的更改内容（包括家居风格等）
2. 提供周围环境内容，不进行自动框选，由用户手动框选
用户确认框选后，进入`##更改预览`生成和预览界面展示

#工作流程

工作流程：

1. 由 Admin 或设计师提供持久化的登录网页或登录接口（如 Hash 值命名的 URL 等），提供免认证登录能力。
2. 用户通过网址登录后进入 Chat 界面，完成 Chat 界面的初始化引导。
3. 初始化引导后，由 Chat 收集用户的基础需求，构建用户画像、用户痛点分析等。
4. 根据相关分析，提供对应的家具设计和家居摆放，直接摆放到 3D 视图中。此时引导用户使用 Agent 相关能力，并提供 Agent 相关能力介绍，如定制家居、定制房间、更改需求、更改对应家居等。
5 如果用户没有想法，那么根据问卷和用户当前的信息进行启发式提问。提问时应当根据当前的信息为用户提供几种推荐选项或者猜测选项，由用户进行选择，或者提供一个入口让用户对此问题进行自己的回答。根据相关的回答，可以优化房间设计、家具相关信息等. 自主进行修改提议，并请用户确认
6. 用户可能在任何时间提供更多的相关信息，需要随时考虑更新用户画像或者用户需求等全局字段
用户对话产生的更改将通过一个表格进行记录，记录的不是原始对话，而是本次更改的具体内容以及用户产生此次更改的依据。如果用户没有提到依据，而只是提出了具体的更改措施，则只记录更改措施和相关的三次对话上下文。

7. 根据所有的输入和用户最后生成的3D图，生成详细的面向设计师的报告。
包括平面布局图、概念风格图和出版效果图，以及通过对话了解到的用户画像、基础需求、痛点和特征提炼等相关用户信息，整合每个决策的原始对话记录。
