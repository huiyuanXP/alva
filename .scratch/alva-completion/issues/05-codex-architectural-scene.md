# 05: 调用Codex生成建筑3D场景

**ID:** ALVA-012

**Parent scope:** T02-D

**What to build:** 用户针对确认后的拓扑点击生成建筑3D，由一次真实Codex生成任务产出对应的三维建筑场景，可预览、确认并重载。

**Blocked by:** 04：修正门窗、校准尺寸并确认拓扑

**Status:** ready-for-agent

**Execution:** 用户已明确本轮只发布细化后的Ticket；本票尚未实施或上线，后续执行指令到达后再开工。

- [ ] 生成阶段必须真实调用Codex；输入包含原图/来源、已确认拓扑版本、校准依据、明确的建筑显示要求，不能仅切换现有Three.js相机冒充AI生成。
- [ ] Codex生成结构化建筑场景：地面、带门窗洞的墙段、必要的门窗框/玻璃、材质及初始相机，构件回指拓扑实体ID。
- [ ] 确认拓扑是硬约束：坐标、开口、房间关系不得被模型私自改写。输出经有限值、单位、引用、几何与开口一致性校验后才进入候选预览。
- [ ] 前端从这份通过校验的输出构建真实可旋转3D；不用一张生成图片或固定example场景冒充当前户型。
- [ ] 记录输入拓扑版本/指纹与生成结果；生成中、失败、取消、可重试状态可见。确认保存后刷新不需再次调用模型；拓扑变更后标记旧3D过期，明确重新生成。
- [ ] 坏输出可有限次数交由Codex修复，仍失败则保留之前结果并报失败，不用未标识的固定渲染兜底报成功。
- [ ] 两种不同布局分别完成真实生成、预览与保存，模型输出构件与屏幕几何可追溯；旧项目不会因新增生成记录丢失保存版本。

**Scope boundary:** 只生成建筑及必要门窗细节，不自动布置示例家具、购买资产或生成施工级结论。生成描述由服务端验证并交给固定渲染器执行，不执行模型返回的任意网页/脚本。

**Development location:** 实施前阅读[当前目录规范与本票落点](../../../docs/PROJECT-STRUCTURE.md)。以其中对应 ALVA 编号的归属为准，不沿用迁移前目录；此链接不改变本票范围、依赖或实施授权。

**Snapshot scope:** 确认操作只更新当前工作状态；只有用户手动点击全局保存才建立存档快照。点击已有快照只读预览，明确恢复才整体替换；不要求逐操作历史、撤销或自动存档。
