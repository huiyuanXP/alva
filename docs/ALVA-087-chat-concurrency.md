# ALVA-087 Chat 与页面并行

用户要求：Chat 工作时右侧问卷和多数操作保持可用；手动移动家具不能让整批建议报废；忙时完成一段问卷只保存，保留发送入口，不打断当前回复。

## 现役行为

- `web/src/main.tsx` 将 Chat（含自动引导）与短时页面写入的忙碌状态分开。问卷、视角、语言、家具拖拽和建议采用不受 Chat 锁定；新 Chat 消息、范围生成和项目切换仍避免重入，阶段切换沿已有取消旧 Chat 流程。请求返回的旧 revision 不覆盖较新的页面状态。
- 生成问卷 Submit 原子保存；原生问卷保留自动保存。空闲时 Submit 仍发送一轮；提交时 Chat 忙碌则只保存，不排自动补发任务。左侧“把问卷的新更改发送给 Chat”始终可见，忙时禁用，空闲后由用户点击。成功批次只标记自身快照，新回答留在下一批，刷新可恢复。
- 生活 MCP `propose_changes`、`suggest_furniture` 仍只生成候选。候选里的 x/y 是绝对目标，采用时按物件 ID 在最新工作稿合并补丁；未被指定的属性和其他物件保持。新候选绑定建筑结构，普通移动、问卷、配色或元数据变化不使其失效；旧家具候选也可通过现行校验采用。
- 采用在现有项目事务中校验选中范围、对象存在性、锁定、边界和碰撞；失败零部分写入，不自动保存快照。单张预览随最新 revision 更新；组级预览单个碰撞不会使其他候选不可读取。预览错误不禁止用户改选范围，最终采用仍完整校验。
- Chat 完成时不因并发家具修改丢弃已生成候选。详细家具建模允许普通移动或问卷变化，仍检查建筑结构、目标类别及最新摆放。新问卷题卡只发布仍匹配回答版本、且不抢占待答段的结果。
