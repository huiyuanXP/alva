# 后续功能任务 Prompt：MCP 优先接入主 Chat

每个获准实施的用户功能 Ticket 都包含以下要求；填写真实模块与工具，不能只粘贴模板。当前066候选使用 `mcp_list_tools` / `mcp_call_tool` 桥接本机HTTP MCP，新增功能登记到所属 `packs`，不依赖旧thread原始dynamicTools目录自动更新。发布状态以 CURRENT 为准。

> 功能：`<名称>`；用户意图：`<自然语言请求>`；所属阶段/MCP：`<户型导入或生活设计>`；工具：`<独立工具名>`；共用业务服务：`<路径>`；用户确认：`<条件>`；持久状态：`<字段>`。
>
> 先读 `AGENTS.md`、`docs/PROJECT-STRUCTURE.md`、`docs/ALVA-065-main-chat-agent.md` 和 ALVA-066 当前实施状态。主入口是登录后左侧 Chat；MCP 是默认优先调用渠道。在同一 Ticket 将功能接入所属 MCP，使用现役 Harness，不让模型绕过工具直接写状态。保留直接控件，与 MCP 共用同一服务端业务逻辑。
>
> 写明工具 schema、返回值、项目/角色/阶段权限、revision、幂等、取消/重试、候选/确认和失效规则。每次只向 Agent 配置所属阶段的一包 MCP，服务端仍校验最新项目状态。辅助模型不继承主 Chat MCP；不临时开放 shell、文件写入或任意 HTTP 工具。使用已验收的原生 MCP 路径；若 ALVA-066 确证网关限制而采用 dynamicTools 桥接，则调用相同 MCP 并保留完整合同，不能称原生已通过。
>
> 附件先真实上传到项目私有暂存区，工具按附件 ID 验证归属并读取；不能凭文件名冒充读取。模型只提出候选，用户确认由服务端核验。问卷草稿不触发家具建议，确认答案才触发。样式先预览后确认且不改几何。界面参数通过受约束 UI action 执行并回执，无回执不能称已生效。
>
> 错误在 MCP 内返回 isError=true 与可解释结构：code、message、retryable、repairActions，并按场景附 currentRevision、字段/对象、confirmationRequired。Agent 必须据此提示具体修复步骤，不能吞错、假报成功或盲目重试。验证桥接保留相同错误语义。
>
> 验收从主 Chat 自然语言开始，记录实际 MCP 工具调用、结果、用户确认和项目重读；覆盖错误输入、越权/跨项目、阶段隐藏、过期状态、取消重试。涉及界面操作要验证实际画面与回执，涉及阶段/会话要验证 Resume 原 thread、摘要送达去重、服务重启及失效摘要。保留独立 run 证据，同步合同、票据交接与 NextTask。只完成 API、按钮或工具注册不能关闭整票。

已有功能补接同样遵循此标准。其他尚未实现业务返回明确不可用及解释，不用空工具或模型回复冒充完成。

诊断类能力须与页面共用业务计算，工具同时返回具体错误码、对象ID/位置、未能完成的检查和修复步骤；不能只回“有问题”或以空候选表示检查通过。确认卡依据须绑定该操作真正依赖的数据；过期后提供重新校验/刷新入口，刷新不得代替用户确认。
