# ALVA-076 阶段导航不再等待模型

## 线上事实与根因

用户报告074/075发布后刷新仍无法自由切换。经用户提供的现行验证码登录生产确认：账号为owner，拓扑/建筑均已确认，两阶段thread均存在，空闲时按钮disabled=false且点击命中按钮自身，并非缺少建筑或被覆盖。

实际英文Living design点击进入living，但返回阶段交接TOOL_FAILED；原切换路由同步执行原thread Resume预检、再注入快照/交接，各自可等待30秒。这段时间前端working让两个按钮都禁用。同时自动引导的busy直接拒绝导航，形成“进入阶段→自动引导→无法立即返回”的体验。075浏览器回归主动屏蔽引导，只覆盖空闲按钮，因此遗漏该路径。

## 修复合同

- 手动阶段导航只持久化目标阶段和带revision的交接摘要，不在导航请求中调用模型。保留两阶段原thread ID及消息；不重开户型、不清除设计。
- 接续的自动引导或用户Chat通过既有runStageChat恢复原thread，附带未送达摘要，并由实际送达回调记录ID。页面切换完成不冒充模型交接已完成；模型失败仍按现有Chat错误/重试处理。
- 建筑确认等业务确认入口保持原有交接行为，建筑未确认不能进入living工具阶段。
- 用户在自动引导或普通Chat期间切换时，先通过现役/chat/cancel停止当前回复，等待旧流收尾、重读revision，再切阶段；不取消正在执行的导入、保存等非Chat操作。
- 两个页签不再因建筑前置直接变成无响应灰按钮；点击living缺少建筑时在页签旁显示原因。只读身份与实际切换中的短暂互斥保留。当前阶段改用蓝底白字，与未选中的页签区分。

这修正了065/066历史“导航请求同步立即Resume/注入”的行为：页面导航与模型恢复分别完成，原thread、摘要去重和MCP阶段隔离保持。
